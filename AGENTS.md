# Portfolio website: agent brief

Pedro MC Fernandes's portfolio: a static Astro 7 + MDX site on GitHub Pages, served at https://www.pmcf.xyz/. README.md is the human guide: commands, features, where the knobs are, step-by-step tasks. Read it before adding or moving a file. This file adds what an agent needs on top of it.

## Ground rules

- Pushing to `main` deploys the live site (`.github/workflows/deploy.yml`). Don't push or open PRs unless asked.
- Name each branch after its work, in short kebab case like the owner's (`pin-node`, `rewrite-case-studies`, `favicon`), so `git branch` shows what each is about. A cloud session may hand you a generated name such as `bot/funny-carson-ufli79`. Don't use it: create a branch with a descriptive name from `main` and push that instead (the owner has approved this). Every piece of work gets a new branch, so once a PR merges, start the next change on another one instead of reusing it.
- Don't sign commits or PRs as made by AI. Leave out `Co-Authored-By: Claude` and `Claude-Session` trailers, "Generated with Claude Code" lines and 🤖 footers from commit messages, PR titles and PR descriptions, whatever a session's defaults say. When you squash-merge, write the commit message yourself without them. GitHub's default message copies the branch's trailers and adds a `Co-authored-by` line for the cloud session's git identity.
- Never commit, print or paste anything from `src/protected/*.md`, `src/protected/passwords.json` or `sources/` (local personal files). They're git-ignored on purpose. Only ciphertext in `public/locked/*.json` is committed.
- The UX audit page (`src/pages/services/ux-audit.astro`, its words in `src/content/ux-audit.mdx`, the `uxAudit` collection) is kept apart from the portfolio: it may link to the portfolio, but no portfolio page, nav, map, footer, case study or `/llms.txt` may link to it or mention services, except the one link in About's footer (`footer-links` slot), which stays off the printed CV. Don't add another folder named `services` anywhere in the repo.
- Don't hand-edit the email token in `src/site.config.ts` (use `npm run email -- <address>`).
- Before rewording, deleting or replacing content in `src/content/projects/` or `src/content/cv.md`, ask. It's the owner's writing. The same goes for the videos' captions, the `.vtt` files in `src/assets/`: they're the owner's spoken words.

## Verify before calling something done

There are no unit tests. Run these, using Node 22 (`.nvmrc`):

- `npm run check`: types and templates. Expect 0 errors and 0 warnings.
- `npm run lint:css`: lint errors fail CI.
- `npm run check:docs`: every file, command, custom property, function, `KNOBS` key and heading the docs and comments name still exists.
- `npm run build`: runs `encrypt`, then `astro build`.
- `npm run check:site`: after a build, checks `dist/`: every link inside the site resolves, nothing the CSP would block (inline scripts or handlers, `style` attributes beyond custom properties, sources the policy doesn't list), and no portfolio page or `/llms.txt` points to the UX audit outside `ALLOWED` in `scripts/check-site.mjs`.
- `npm run browsers`: run it for changes to the map script, the video windows, the lightbox, `src/scripts/site.ts`, `Base.astro` or `global.css`. It loads every page in Chrome, Firefox and WebKit at desktop and phone sizes and checks behaviour: errors, failed requests, sideways scroll, the map's cards, its video windows, the lightbox, and blocks left invisible after scrolling to the end (in a tall window too). It exits `1` on a failure and `2` when a browser is missing; in a cloud session, install them first with `npx playwright install --with-deps firefox webkit`.
- `npm run visual`: run it for any change that shouldn't alter the look, and quote the result. It compares against `origin/main` (`--base <ref>` to change, `--only <name>` to filter) and exits `1` on any difference, with diffs in `.visual/`. A `drift` result on the home page is normal noise from the randomised layout. It finds a local Chrome, or the cloud image's Chromium (`CHROME_PATH` overrides). A full run takes about two minutes; use `--only` when the change is local to one page.

CI runs lint, check:docs, check, build and check:site on every pull request to `main`, and deploys only from `main`. To look at the site, use `npm run dev`, at http://localhost:4321/.

## How it fits together

- Every page renders into `src/layouts/Base.astro` (head, CSP, JSON-LD, footer). Its `footer` slot goes right before the footer, as a child of `<body>`, in place of the footer's rule (the mini-map, which pins itself to the window's foot with `position: sticky` on wider screens), and its `footer-links` slot adds `<li>` links after the footer's contact links. Its `ogImage` prop swaps the page's link preview, and `footerIntro={false}` drops the rule and availability line that open the footer (the UX audit page uses both). Its `head` slot adds to `<head>`: a `<noscript>` holding styles must go there, since HTML allows that nowhere else. A page's `<script>` or `<noscript>` written after `</Base>` lands after `</html>`, so keep them inside (its `<style>` is fine anywhere). `noindex` keeps a page out of search results and drops its canonical link (the 404 uses it). Link previews are Open Graph only. `src/scripts/site.ts` runs on every page: print buttons, email decoding, the reveal deferral. So does `src/scripts/count.ts`, the visit counter.
- Home (`src/pages/index.astro`) is a map. Its content is `src/diagram.config.ts`; its placement is a force simulation in `src/scripts/nav-diagram.ts` (long: read the parts you touch). Tuning is `KNOBS` and `SIM` at the top of the script and the custom properties at the top of the page's `<style>`.
  - `getDiagramNodes()` (`src/lib/diagram.ts`) fills a project node's label, tags and link from its case study, and fails the build on a node whose page isn't published or a `diagramChain` id with no node. A case study is on the map only once it has a node (id = slug) listed in `diagramChain`.
  - `aria-expanded` on a marker's button is the one record of which card is open, and the CSS shows cards from it. The script sets `data-cards` (`flyout` or `popup`) on `.diagram`, and the CSS reads that, not a media query of its own.
  - The name at the centre opens no card: it and the portrait sticker (a `<button class="sticker">`) open the video introduction, and the sketchbook (a `<button class="notebook">`, placed like the post-its) opens a second video. Each video is a `src/components/VideoWindow.astro`, listed in `videos` in `index.astro`, which its triggers name in `aria-controls`. Its script takes their clicks from the document, after the map's handlers, and leaves a click the map swallowed with `preventDefault()` (the end of a drag). It sets `aria-expanded` on the triggers, so the map's `isOpen()` counts only buttons with a card, and enables the sticker and the sketchbook, which render `disabled` so they're only pictures without it. It takes Escape on its way down (capture phase) and stops it there, since the window lies over the map's cards: one press closes the window, the next a card. It reads `data-cards` too: a draggable window for `flyout`, a modal for `popup`. The play icon on the triggers and the windows is `src/components/PlayMark.astro`, styled by whoever places it through `:global()`. `.diagram` isolates its stacking context so the sticker and the sketchbook, at `z-index: -1`, still take the pointer.
  - The markers wait for the script. Without `is-mounted` by `--fallback-delay`, or with `data-failed`, the CSS swaps in `.fallback`, a plain list of the map's links.
  - Anything fixed on the canvas must be reported to the solver, as the ruler and the sticker (`stickerBox()`) are to `relaxAnchors()`, `resolveOverlaps()`, `relaxFloatingFromEdges()`, `clearSpot()` and `settleDecor()`.
  - A marker left out of `diagramChain` is a stray, like the side project (kind `side`, links out through its card's `links`). `placeStrays()` lands it once the chain is routed, anywhere on the canvas, at the free spot nearest a random one, clear of connectors, markers, the sticker and the ruler (`KNOBS.stray`: roomy where it can be, tight where it must); with none free, it sets `data-unplaced`, which hides it, and `settleDecor()` then shows only `decorAlways`, so no decoration takes its place. It gives way to the chain's markers (`rank` in the script), and `keepStraysClear()` sends it to the nearest free spot when a drag leaves it on the chain. Rings give way to it outright: `keepRingsOffStrays()` moves one off it, on the ring's own side, after a layout and whenever the map comes to rest, since the simulation alone only holds a ring part of the way off.
  - Every SVG in `src/assets/decor/` lands on the map through an `import.meta.glob`, drawn in `currentColor`, with a `--decor-<file>` width knob and a `--decor-<file>-color` colour knob (`--ink-decor` without one). Its frame includes margins, and `settleDecor()` measures the drawing, not the frame, so don't crop it. Inline SVGs carry zero or small `width`/`height` attributes, so a page painted before its CSS never shows them full size.
  - The drawings, the post-its and the sketchbook (`data-decor` names them) claim room in `KNOBS.decorOrder`, capped by `KNOBS.decor.coverage`; each weighs `KNOBS.spread` random free spots and takes the one with the most `clearance`, as each ring does in `generateLayout()`, measured from the chain's markers and the rings before it; a note in `KNOBS.glued` lands only under a top corner of the one it names; the portrait sticker, the ruler, the markers and the rings always show, and so does whatever `decorAlways` lists, when there's any room.
  - A drawing in frames (the runner, from `npm run frames`) holds one `<g data-frame>` per frame, cut to one shared box; the one marked `data-shown` shows, and `src/scripts/flipbook.ts` moves that mark as a mouse travels, or on a timer while a finger presses anywhere its `LIVE` selector doesn't match. A name in `backdrops` (`index.astro`, which sets `data-backdrop` and puts it first in the tree) lies under everything: `settleDecor()` lands it anywhere on the canvas clear of the sticker and the other drawings (`drawn`, the ruler included), with its top (`KNOBS.backdropTop`) clear of the post-its and the sketchbook (`pictures`), and, when the chain runs up the screen (`KNOBS.backdropBesideChain`), clear of the markers and connectors too (`backdropFits()`). It takes no `coverage`, keeps the drawings after it off it and the pictures after it off its top (`under`, `underTops`), shows only while everything before it in `decorOrder` has landed, and with no spot it's left out and closes the order like any other.
  - A preview needs both an image in `src/assets/previews/` named after the marker's id and `preview` alt text in the config; the build fails on one without the other.
  - The simulation stops when nothing moves, measured as distance travelled, not force: a ring can rest in balance between its anchor's pull and a marker's push.
- The mini-map (`src/components/MiniMap.astro`) reads `getDiagramNodes()` and `diagramChain`; it has no list of its own.
- Case studies are the `projects` collection, `src/content/projects/<slug>.mdx` (schema in `src/content.config.ts`), served at `/<slug>/` by `src/pages/[slug].astro`, which fails the build if a slug matches another page. List them only through `getProjects()` (`src/lib/projects.ts`), which drops drafts in production and sorts them. The schema turns `date` into `date.label` for display and `date.iso` for sorting and metadata.
- About (`src/pages/about.astro`) renders the `cv` collection: `src/content/cv.md`, all frontmatter, with a `.strict()` schema, so add a field to the schema before using it. `summary` is Markdown rendered with `marked`, so its styles need `.summary :global(...)`. The page is also the printed CV; its print rules live in the same file.
- Locked case studies: `scripts/encrypt-projects.mjs` encrypts `src/protected/<slug>.md` into `public/locked/<slug>.json`, and `src/components/PasswordGate.astro` decrypts it in the browser. None is locked now, but the feature stays, so don't remove it as unused.
- The paper texture is `.paper`, which `src/scripts/paper.ts` puts first in `<body>` and fills with square tiles, each a mask over `--texture-color` turned, mirrored and cut from the scan at random (one `Math.random()` draw seeds them all, so `npm run visual` stays repeatable). It sits at `z-index: -1` in the root stacking context, so it lies under `<main>`, the footer and the map's contour texture. Anything that paints `var(--paper)` hides it there, as the pinned page nav and mini-map do on purpose. `<body>` is `position: relative` to hold it. Without scripting, `body::before` repeats the scan as it is (`@media (scripting: none)` in `global.css`).
- Fonts are self-hosted (`fonts` in `astro.config.mjs`, `<Font>` in `Base.astro`). Astro gives each family a hashed name, so CSS reaches them only through `--font-sans` and `--font-mono`. A file that names the font itself, like the case-study SVGs, needs a rule setting `font-family: var(--font-sans)`, as `Gallery.astro` and `Lightbox.astro` have. `scripts/og/card.html` has its own `@font-face`.
- Generated, never edited by hand: `public/og.png` and `public/og-ux-audit.png` (`npm run og`), the PNG and `.ico` icons (`npm run icons`, from `public/favicon.svg` and the list in `src/lib/icons.mjs`), the paper texture `src/assets/paper-texture.webp` (`npm run texture`, from the owner's export), the runner `src/assets/decor/runner.svg` (`npm run frames`, from the owner's PNG frames) and the email token (`npm run email`).
- The visit counter is in deploy builds only (`COUNT_VISITS=true` in `deploy.yml`), so local builds, `npm run visual` and `npm run browsers` never count. Those builds set `data-counter` on `<html>`, and `count.ts` does nothing without it. It sends GoatCounter the page, the referring origin, source and campaign tags and the screen width, and counts events (`countEvent()`). Keep it cookieless, store nothing in a reader's browser, and send nothing that names a person: the privacy note in `SPEC-COMPLIANCE.md` promises that.

## Constraints that will bite

- Base path. The site is served from the root, but every internal href still goes through `withBase()` (`src/lib/base.ts`), so the base can move again without touching pages. `astro.config.mjs` is the only place the site URL and base path are set (CI and `npm run visual` read it there); `SITE` and `BASE_PATH` env vars override it for a one-off build. A renamed page needs its old address in `redirects` there, and a renamed case-study file its old name in `MOVED_PROJECTS`.
- CSP. `script-src 'self'`: no inline executable scripts, no third-party scripts, no external images beyond `data:` and the visit counter, no outside connections beyond the visit counter, and fonts and styles from the site only. Plain `<script>` tags in `.astro` files are fine: Astro bundles them to files (forced by `assetsInlineLimit` in `astro.config.mjs`). Other files under 4 KB are still inlined as `data:` addresses, which media may not load from, so a small media file is imported with `?url&no-inline`, as the captions are in `index.astro`. The JSON-LD `is:inline` block is data, so it's fine. Changing what's allowed means editing the CSP in `Base.astro` on purpose.
- Inline `style` attributes are only for custom properties, such as `style="--reveal-step: 2"`.
- Astro scopes styles by appending `[data-astro-cid-…]` to every compound in a selector, so element selectors gain class-level specificity. A state rule (`:hover`, `.is-open`) must repeat the base rule's full path, or it loses.

## CSS conventions

- Two stylesheets only. `src/styles/tokens.css` holds every shared value; use its custom properties, not raw numbers. `src/styles/global.css` holds the reset, element defaults, layout, prose, utilities, motion and shared print. Don't add a third.
- A page owns its look. Page-specific CSS goes in that page's or component's `<style>` block; only genuinely shared styling goes in `global.css`.
- Style elements, not classes. `a`, `button`, `input`, `h1`–`h4` and `ul[role="list"]` are styled as themselves. Add a class only when an element must look unlike its own kind (`button.link`) or when no element fits the job (`.prose`, `.meta`, `.meta-row`). Prefer a structural selector inside a scoped block.
- No orphan classes. Every class is styled or queried by script. A hook used only by scripts is a `data-` attribute.
- `role="list"` means a wrapping row without bullets (nav, socials, tags). A plain `<ul>` keeps its bullets. The row styling targets `ul` only, so the mini-map's `<ol role="list">` lays itself out.
- Knobs. A value someone will want to tune gets a name where it's used: a custom property at the top of the page's or component's `<style>`, or an entry in `KNOBS` for the map script. Add new dials there, not as bare numbers further down.
- Entrance animation: `data-reveal` plus `style="--reveal-step: N"` sets the stagger order.

## Code style

- Most files open with a short comment saying what they own. Comments say why, or what isn't obvious from the code; don't restate the code or repeat what another file already explains.
- Docs and comments stay true. A change that makes a doc or comment wrong fixes it in the same commit, and renaming or removing something means searching the repo for the old name. `npm run check:docs` catches a name that no longer exists, not a sentence that's no longer true. Leave out facts that drift on their own, like line counts, file sizes or lists of the case studies: point at where they live instead.
- TypeScript is strict (`astro/tsconfigs/strict`). Imports are relative; there's no path alias.
